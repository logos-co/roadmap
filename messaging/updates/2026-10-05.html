2026-10-05 Messaging Weekly

Oct 05, 20264 min read

  • messaging-updates

Highlights

  • Logos Delivery:
    • v0.39.0 released.
    • Messaging API — General Availability milestone closed, with Integrate Rate Limit Manager as its last deliverable.
    • RLN on Logos Blockchain milestone closed: Implement pluggable RLN membership interface and Enable RLN in Logos Devnet.
    • A network of Messaging API nodes can now be set up and driven from the node CLI and REST, with operator docs (#4386, #4389, #4387).
  • Status:
    • status-go and Status App both run logos-delivery v0.39.0 (#7860, #22606); Integrate Messaging API in status-go closed.

Logos Delivery

Messaging API — General Availability

  • [Deliverable] Reliability and scale validation with DST

    • achieved:
      • fix(conf): give logosdeliverynode a node config of its own (#4386).
      • fix(conf): configure the Messaging API from the node CLI — --reliability and --anonymity-level, so a network without Store nodes can run with reliability off (#4389).
      • docs(messaging): document how to run and use Messaging API nodes (#4387).
      • fix(rest): answer 429 with Retry-After when the send queue is full, instead of 500 (#4392).
      • feat(rest): list the messaging subscriptions (#4393).
      • fix(messaging): confirm every propagated send against Store (#4351).

  • [Deliverable] Integrate Rate Limit Manager

    • achieved:
      • Rln id release — a failed proof generation gives its message id back, so a retry reuses it instead of spending a new one the rate limit manager already charged (#4382).
      • closed the remaining issues: Allow initialize rate limit manager (#3838).

  • [Deliverable] Integrate Mix into Messaging API

    • next:
      • Mix replies can fail for senders behind NAT (#4357).

RLN on Logos Blockchain

  • [Deliverable] Implement pluggable RLN membership interface

    • achieved:
      • Rln interfaces — one config surface for both RLN backends, so an operator needs to know nothing about which one is in use (#4338).

  • [Deliverable] Enable RLN in Logos Devnet

    • achieved:
      • fix: message ids able to repeat within same epoch — two proofs sharing a nullifier in one epoch are exactly what recovers a sender’s identity secret (#4366).
      • RLN EVM: persistent message id store — a node restarted mid-epoch no longer reuses ids already carried in proofs it sent (#4385).
      • fix(rln): ignore instead of reject messages with unknown root — an honest peer’s valid message was rejected and its forwarder penalised by gossipsub (#4377).
      • fix(rln): report RLN READY only once a proof can be generated (#4381).
