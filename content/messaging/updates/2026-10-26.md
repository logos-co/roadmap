# Maintenance

- achieved:
  - [Octopus](https://github.com/logos-messaging/octopus): a decentralized CI over logos-delivery, taken from nothing to [v0.4.0](https://github.com/logos-messaging/octopus/releases/tag/v0.4.0) — LogosTransport over the Python bindings, presence and scheduler, coordinator failover and discovery, JIT `actions/runner` per job, job log streaming, trust policy, `octopus init`, OIDC pick mode, job isolation on macOS and Linux, and release artifacts; it now runs its own unit tests on team machines ([#88](https://github.com/logos-messaging/octopus/pull/88)) and was presented at the hackathon.
  - build: use a different mingw64 path in build-windows ([#4604](https://github.com/logos-messaging/logos-delivery/pull/4604)).
  - upstream: reset the stream on an oversized pubsub frame instead of half-closing it ([libp2p#3320](https://github.com/iftech/nim-libp2p/pull/3320)).
- next:
  - SDS: a full ~18.75 KB bloom filter rides every message and is not configurable ([nim-sds#111](https://github.com/logos-messaging/nim-sds/issues/111)) — shrink it ([nim-sds#112](https://github.com/logos-messaging/nim-sds/pull/112)) and expose the parameters in `SdsConfig` ([#4606](https://github.com/logos-messaging/logos-delivery/issues/4606)).
  - raised: one message above a peer's `--max-msg-size` stops all relay from the sender to that peer ([#4608](https://github.com/logos-messaging/logos-delivery/issues/4608)), the messages_lookup query metric stopped counting hash lookups ([#4598](https://github.com/logos-messaging/logos-delivery/issues/4598)), deprecate the Postgres capacity retention policy ([#4597](https://github.com/logos-messaging/logos-delivery/issues/4597)).
