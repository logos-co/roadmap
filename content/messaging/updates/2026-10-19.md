## Highlights
<!-- Please Add the team weekly highlights here -->

- Logos Delivery:
  - status.prod store nodes froze on Postgres after the v0.39.1 deploy ([#4526](https://github.com/logos-messaging/logos-delivery/issues/4526)); root-caused and fixed — database calls never block the event loop again ([#4531](https://github.com/logos-messaging/logos-delivery/pull/4531)) and hash queries no longer plan every partition ([#4532](https://github.com/logos-messaging/logos-delivery/pull/4532)). [v0.39.2](https://github.com/logos-messaging/logos-delivery/releases/tag/v0.39.2) shipped with the fixes.
  - the message-sending machinery was rewritten: concurrent sends, one task pipeline for mix, RLN, ephemeral and reliability ([#4517](https://github.com/logos-messaging/logos-delivery/pull/4517)).
  - store sync now follows the WAKU-SYNC wire formats, so an implementation written from the spec can sync with us ([#4571](https://github.com/logos-messaging/logos-delivery/pull/4571)).
  - codecs moved to proto3 and minprotobuf is retired ([#4488](https://github.com/logos-messaging/logos-delivery/pull/4488)); every store, lightpush and sync read is now size-bounded ([#4489](https://github.com/logos-messaging/logos-delivery/pull/4489)).

# Maintenance

- achieved:
  - status.prod outage: v0.39.1 store nodes froze on Postgres ([#4526](https://github.com/logos-messaging/logos-delivery/issues/4526)) — a synchronous `PQprepare` blocked the event loop behind a queued partition DDL ([#4531](https://github.com/logos-messaging/logos-delivery/pull/4531)), hash-only queries planned every `messages_lookup` partition and ran for up to 1,750s ([#4532](https://github.com/logos-messaging/logos-delivery/pull/4532)); v0.39.2 changelog ([#4546](https://github.com/logos-messaging/logos-delivery/pull/4546)).
  - [Review implementation of Store Sync protocol](https://github.com/logos-messaging/pm/issues/469): follow the WAKU-SYNC wire formats ([#4571](https://github.com/logos-messaging/logos-delivery/pull/4571)), clamp the ranges of sessions started by a peer ([#4535](https://github.com/logos-messaging/logos-delivery/pull/4535)) and of our own to the time retention ([#4478](https://github.com/logos-messaging/logos-delivery/pull/4478)), transfer reads up to `--max-msg-size` and reset oversized sessions ([#4547](https://github.com/logos-messaging/logos-delivery/pull/4547)), skip messages a peer refused as too large ([#4562](https://github.com/logos-messaging/logos-delivery/pull/4562)), let a stop end the transfer loop ([#4551](https://github.com/logos-messaging/logos-delivery/pull/4551)), create the partitions for the hours before the node start ([#4524](https://github.com/logos-messaging/logos-delivery/pull/4524)).
  - send machinery: rewrite the messaging send tasks for concurrency ([#4517](https://github.com/logos-messaging/logos-delivery/pull/4517), closes [#4328](https://github.com/logos-messaging/logos-delivery/issues/4328)); refuse API calls on a node that is not started ([#4586](https://github.com/logos-messaging/logos-delivery/pull/4586)); free the REST and metrics ports on stop ([#4585](https://github.com/logos-messaging/logos-delivery/pull/4585)); document that `stop_node` keeps the event listeners ([#4583](https://github.com/logos-messaging/logos-delivery/pull/4583)).
  - relay, sharding and CLI conformance: don't hand a duplicate publish to own handlers again ([#4519](https://github.com/logos-messaging/logos-delivery/pull/4519)), content-topic unsubscribe keeps other topics on the shard ([#4518](https://github.com/logos-messaging/logos-delivery/pull/4518)), subscribe to configured shards on start under static sharding ([#4516](https://github.com/logos-messaging/logos-delivery/pull/4516)), `--shard` limits the relay shards under autosharding ([#4513](https://github.com/logos-messaging/logos-delivery/pull/4513)), refuse shards of another cluster ([#4514](https://github.com/logos-messaging/logos-delivery/pull/4514)), stop mapping `--cluster-id=2` to the logos.dev preset ([#4515](https://github.com/logos-messaging/logos-delivery/pull/4515)), let `--preset` set max-msg-size ([#4567](https://github.com/logos-messaging/logos-delivery/pull/4567)), keep topic health in sync across stop/start ([#4568](https://github.com/logos-messaging/logos-delivery/pull/4568)), relay a message encoded at the max message size ([#4578](https://github.com/logos-messaging/logos-delivery/pull/4578)), keep connected peers out of CannotConnect ([#4512](https://github.com/logos-messaging/logos-delivery/pull/4512)).
  - wire and protocol hygiene: move the codecs to proto3 and retire minprotobuf ([#4488](https://github.com/logos-messaging/logos-delivery/pull/4488)), bound the size of store, lightpush and sync reads ([#4489](https://github.com/logos-messaging/logos-delivery/pull/4489)), deprecate the archive capacity retention policy ([#4593](https://github.com/logos-messaging/logos-delivery/pull/4593)), non-`My` getNodeInfo ids with the old ones as deprecated aliases ([#4577](https://github.com/logos-messaging/logos-delivery/pull/4577), [module#168](https://github.com/logos-co/logos-delivery-module/pull/168)).
  - upstream gossipsub: check the seen-cache before local delivery on publish ([libp2p#3270](https://github.com/iftech/nim-libp2p/pull/3270)), don't re-deliver already-seen published messages locally ([libp2p#3275](https://github.com/iftech/nim-libp2p/pull/3275)).
  - nim-ffi poll model: let a host poll a context for its events ([#199](https://github.com/logos-messaging/nim-ffi/pull/199)), answer requests through poll with an id per request ([#200](https://github.com/logos-messaging/nim-ffi/pull/200)), give the C exports a request id instead of a callback ([#201](https://github.com/logos-messaging/nim-ffi/pull/201)), make the request payload cap opt-in ([#234](https://github.com/logos-messaging/nim-ffi/pull/234), [nim-sds#109](https://github.com/logos-messaging/nim-sds/pull/109)).
  - status fleet: bump logos-delivery to v0.39.2 in status-go ([#7936](https://github.com/status-im/status-go/pull/7936)) and in Status App ([#22798](https://github.com/status-im/status-app/pull/22798)), drop the legacy-store protocol on prod ([infra-status#71](https://github.com/status-im/infra-status/pull/71)) — Deploy v0.39.1 in the status fleet ([#4371](https://github.com/logos-messaging/logos-delivery/issues/4371)) closed, bump kuma's wakucanary to a current logos-delivery ([infra-hq#322](https://github.com/status-im/infra-hq/pull/322)).
