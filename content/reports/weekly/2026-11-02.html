This week, technically

Tor

tor_module runs Arti in its own process — modules reach it with HTTP/2 requests over IPC, so TLS ends inside Logos. The SOCKS port on 127.0.0.1:9250 is on by default (the Bitcoin wallet's peers need raw TCP), a failed exit is retried on a fresh circuit, and Tor now joins the network on Windows too. The Tor app shows status, join progress, usage and logs. The Zcash node and wallet core use it over IPC, the Bitcoin node module uses it as its default proxy, and both wallets have a Network privacy block explaining what each option reveals.

Status: merged; not in the catalog

Wallet data unlock

Each seed has one unlock key, which every holder of the seed can give: keystore, Keycard (after its PIN), Keycard Shell, or QR signer over one round trip. The QR scanner shows a request for that key only when the QR signer asks for it, so other modules can't phish it. The signer manager unlocks each wallet once per session and hands each module keys of its own; the keystore index, tx history, Ethereum contacts and settings, and Bitcoin wallets and sends are sealed under those keys. Opening a wallet is now the user's consent in the Signer app, with no password sent along. The account kit's LockedBanner is in the Ethereum, Bitcoin and Uniswap apps, the Keycard app shows locked wallets as Locked, and the signer CLI gets the same calls for headless use.

Package integrity

Basecamp re-hashes an installed package's files against manifest.json and checks manifest.sig for signed packages before loading it; a failing required dependency blocks the module, a failing optional one is skipped (bundled modules and standalone mode are not checked). The package manager hash-checks every install under every signature policy, reports extraction and staging failures accurately, and protects its reserved file names. liblgx hashes in 1 MiB chunks (523 → 230 ms on a 102 MB package), has a thread-safe init, and skips lgpm's .lgpm-source sidecar. The matching SDK change was reverted the same week (it needed a dropped liblogos change), so the check stays Basecamp-only.

Status: merged, not yet in a Basecamp release

Basecamp onboarding

At first run, new users pick “Let's go” (GitHub and Logos Storage) or “Advanced setup”, which adds a Logos Storage start-up step; existing users skip onboarding. The downloader starts only after a source is chosen, and under GitHub-only storage_module is unloaded unless something else uses it. UI backends as core modules

A ui_qml app can opt in with "backend": "module" — its .rep backend is built as a core module <app>_backend and shipped in the app's own .lgx, named by the signed manifest (logos-package 0.7.0); the view connects over a private channel with a one-time secret. Basecamp starts the backend when the app opens and shows a panel to reopen the app if the backend stops. The Package Manager is the first app on it; the ui-qml-backend template and a migration guide cover porting other apps.
