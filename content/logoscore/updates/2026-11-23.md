# Logoscore Weekly Update — 2026-11-23

## Highlights

## This week, technically

| Area | What changed | Status | PRs |
|---|---|---|---|
| Design system: phone, tablet and desktop | Sizes that were hard-coded in the controls now come from theme tokens, so a size changes in one place. On desktop nothing looks different. A density setting (compact, comfortable or touch) scales the controls; touch is the default on Android and iOS, and keeps every tap target at least 44 px. Each view knows its own width class (phone, tablet or desktop). A new `Logos.Layouts` module holds layouts that arrange themselves by that width: page bar, list → detail, sections (no ☰ drawer), card grid, forms, welcome, and `LogosSidePanel` for a page with a panel beside it. The table drops low-priority columns when narrow, turns rows into cards on a phone, and gives each row a ⋯ menu, so no action needs hover or double-click (Alisher's RESPONSIVE.md §3.5). The storybook previews any page at phone or tablet width and marks what overflows or is too small to tap; a test fails if any page doesn't fit a phone. A new guide, `docs/responsive.md`, explains it all. Tests also pass on Qt 6.7, which the Windows build uses | merged; not yet used by Basecamp or the apps | [logos-design-system#76](https://github.com/logos-co/logos-design-system/pull/76), [#77](https://github.com/logos-co/logos-design-system/pull/77), [#78](https://github.com/logos-co/logos-design-system/pull/78), [#79](https://github.com/logos-co/logos-design-system/pull/79), [#80](https://github.com/logos-co/logos-design-system/pull/80), [#81](https://github.com/logos-co/logos-design-system/pull/81), [#82](https://github.com/logos-co/logos-design-system/pull/82) |
| Package Manager installs only what Basecamp approved | Every install and upgrade is now checked against Basecamp's approval before anything is queued. Before, an approval that named neither a plan nor a file could still install: the package was looked up by name in the catalogue, or whatever file was waiting under that name was taken. Unused selection code was removed | merged; not in a Basecamp release | [logos-package-manager-ui#107](https://github.com/logos-co/logos-package-manager-ui/pull/107) |
| Intents as a core module | New repo [logos-intents-module](https://github.com/logos-co/logos-intents-module). Some requests need a person: approve a signature, pick a wallet, open an app. `intents_module` routes them from the module that asks to the module that provides, and only the requester can read the result. This is the broker that used to live inside Basecamp, now a core module, so the `logoscore` daemon can host it for `logosctl` and CLI apps too. Basecamp runs it behind `--intents-module`, in development builds only. Package Manager has been tested on it inside a full Basecamp: cancelling and approving installs, uninstalling, installing a local file, and another app asking Package Manager to show a package. Still missing: a list of requests waiting for a person, follow-up requests from a provider, `basecamp://` links, and porting the apps. Fixes from a review were merged on 2026-11-23 | work in progress; repo public, first commit 2026-11-20; the Basecamp, Package Manager and SDK changes are on local branches | [logos-intents-module@b5bb3c7](https://github.com/logos-co/logos-intents-module/commit/b5bb3c7), [logos-intents-module#1](https://github.com/logos-co/logos-intents-module/pull/1) |
| Zcash node: Zebra 7.1.0 and in-memory JSON-RPC | Zebra moves to 7.1.0, a security release (ten advisories, no consensus change). The zebrad module gets `rpc()`, which makes a JSON-RPC call in memory with no port and no cookie. Only an allowlist of methods answers (32 on every network, 7 more on regtest), and `stop` is always refused. `grpc()` is now open to every module. Regtest upgrades can be set with `activationHeights`, without a file. Blocks mined just before a stop are no longer lost on regtest. CI now also builds aarch64-linux | merged; not in the catalog | [logos-zebra-nix#7](https://github.com/logos-co/logos-zebra-nix/pull/7), [#8](https://github.com/logos-co/logos-zebra-nix/pull/8), [logos-zebrad-module#8](https://github.com/logos-co/logos-zebrad-module/pull/8), [#9](https://github.com/logos-co/logos-zebrad-module/pull/9) |
| Bitcoin node | `rpc()` in the bitcoind module is open to every module and the host; the method allowlist, including the regtest-only mining rule, stays (0.2.1). The node module's lock picks up fixes for two RustSec advisories | merged; not in the catalog | [logos-bitcoind-module#4](https://github.com/logos-co/logos-bitcoind-module/pull/4), [logos-bitcoin-node-module#10](https://github.com/logos-co/logos-bitcoin-node-module/pull/10) |
| EVM keys: an emptied wallet keeps its recovery phrase | Once a wallet's last account went, its saved recovery phrase belonged to no wallet any more, and Remove wallet left it on disk. Now the wallet keeps it: its card shows the phrase, Add accounts… uses it, and Remove wallet deletes it | merged; not in the catalog | [logos-evm-keystore-module#47](https://github.com/logos-co/logos-evm-keystore-module/pull/47), [logos-evm-keystore-ui#32](https://github.com/logos-co/logos-evm-keystore-ui/pull/32) |
| Nix cache signing keys rotated | Both Logos nix caches (`public` and `ci`) changed their signing keys on 2026-11-19, so CI could no longer use anything from them. The shared cache action, the Windows cross-build and other repos now trust the new keys | merged | [setup-nix-cache-action#13](https://github.com/logos-co/setup-nix-cache-action/pull/13), [logos-windows-ci#17](https://github.com/logos-co/logos-windows-ci/pull/17), [logos-docs#626](https://github.com/logos-co/logos-docs/pull/626), [logos-json-rpc-bridge-py#3](https://github.com/logos-co/logos-json-rpc-bridge-py/pull/3) |
