# Logoscore Weekly Update — 2026-11-09

## Highlights

## This week, technically

| Area | What changed | Status | PRs |

| Package trust | Each install dialog (the Package Manager's install and upgrade dialogs, and the App Manager) says who signed every package the install would bring. A damaged or wrongly signed package can't be installed. "Trust & install" trusts only the publisher of the package the dialog is about. A publisher that uses a trusted name with another key, or a name that reads as Logos, is flagged and never offered. The Package Manager installs exactly the plan Basecamp approved, release by release, and an upgrade checks its replacement in full before it removes the installed copy. Only Basecamp and the Package Manager's backend may call `package_manager` and `package_downloader`. Settings → Trusted Publishers lists the keyring, and any publisher can be deleted. The downloader no longer picks a release whose manifest names another package, which could have installed over a core module | merged, not yet in a Basecamp release | [logos-basecamp#536](https://github.com/logos-co/logos-basecamp/pull/536), [logos-package-manager-ui#103](https://github.com/logos-co/logos-package-manager-ui/pull/103), [#104](https://github.com/logos-co/logos-package-manager-ui/pull/104), [#106](https://github.com/logos-co/logos-package-manager-ui/pull/106), [logos-package-downloader#57](https://github.com/logos-co/logos-package-downloader/pull/57), [logos-package-downloader-module#63](https://github.com/logos-co/logos-package-downloader-module/pull/63) |
| Themes | A theme is a data-only `theme.json` that recolours the design system's palette. It is parsed in C++ against a whitelist and never run as QML or JS, and colours it leaves out come from Dark. Settings → Appearance lists Dark and the added themes with a preview, switches every view at once with no restart, and adds or removes themes. Apps can read the theme but not change it. The palette is now also resolved in C++, so the shell's own backgrounds, tab bars and window palettes follow the theme: before, a light theme put white text on a light background. A new `primaryForeground` token fixes text on primary buttons under a light primary | merged, not yet in a Basecamp release | [logos-design-system#71](https://github.com/logos-co/logos-design-system/pull/71), [#72](https://github.com/logos-co/logos-design-system/pull/72), [#75](https://github.com/logos-co/logos-design-system/pull/75), [logos-basecamp#537](https://github.com/logos-co/logos-basecamp/pull/537), [#556](https://github.com/logos-co/logos-basecamp/pull/556) |
| Basecamp fixes | The docked-layout shortcut (Ctrl/Cmd+Shift+L) keeps the welcome page out of side-by-side mode, and Settings explains the experimental docked layout. Clicking an app tile's state badge now opens the app. The intent registry no longer logs its provider list on every download progress update. Design-system text and tooltips are plain text by default, so a name from outside an app can't restyle itself | merged, not yet in a Basecamp release | [logos-basecamp#538](https://github.com/logos-co/logos-basecamp/pull/538), [#557](https://github.com/logos-co/logos-basecamp/pull/557), [logos-design-system#70](https://github.com/logos-co/logos-design-system/pull/70) |
| Storage node on demand | The package downloader starts its storage node only for the first download from a `logos:` URL, or earlier when asked with `startStorage()`. Basecamp asks for it, so it still comes up at launch, and a node stopped in the Storage app restarts with the next download. `logosctl` never asks, so a daemon runs no storage node unless a download needs one | merged | [logos-package-downloader-module#62](https://github.com/logos-co/logos-package-downloader-module/pull/62), [logos-basecamp#535](https://github.com/logos-co/logos-basecamp/pull/535), [logos-logoscore-cli#198](https://github.com/logos-co/logos-logoscore-cli/pull/198), [logos-package-manager-ui#102](https://github.com/logos-co/logos-package-manager-ui/pull/102) |
