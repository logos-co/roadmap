## Logos Core

- PoC for the new Core architecture C3A (CDDL Contract Commitment Architecture), as a proof of concept alongside the current Core.

## Basecamp and Apps

- Bitcoin Wallet and Bitcoin Node (`bitcoind`), with supporting modules.
- Zcash Wallet and Zcash Node (`zebrad`), with supporting modules.
- Revamped Signer for the Ethereum and Bitcoin wallets, with a unified Keystore and Keycard support.
- Basecamp improvements:
  - UI backends as Core modules, with one reference app ported and a QML-only UI path.
  - Run apps standalone through Basecamp.
  - Choose GitHub, Storage, or both as download sources during onboarding; show the source during downloads.
  - Package signature checks, trusted-key management, and in-app Basecamp updates.
  - Prompt to terminate modules that are slow to unload.

## Blockchain

### Base Layer

- Eras: chain behaviour and consensus parameters can change through a hard fork at an era boundary.

### LEZ

- Transactional actor model: programs compose atomically and exchange messages asynchronously across public and private execution.
- Privacy-preserving transaction fees: private transactions pay fees inside their proof; wallets estimate fees through dry runs.
- Atomic deposits from the base layer into LEZ, removing the previous finality wait for deposits.
- LEZ sequencer runs as a Logos Core module.

## Messaging

### Delivery

- Messaging API reaches General Availability, with reliability and scale validated by DST.
  - `send` returns the message hash and fails fast on rate limits.
  - Newly subscribed content topics are not backfilled from Store.
- Monthly `logos-delivery` releases, followed by updates to the Delivery module.
- At least half of the baseline technical-debt issues closed; target modular architecture agreed.
- Store Sync hardening; DST sign-off is planned for v0.5.

### Chat

- Self-healing group chats: recovery from missed messages and group forks, with SDS and Ordering Policy integration.
- Tools to diagnose group forks and measure group reliability.

## AnonComms

- RLN membership allocation service: end-to-end testnet membership allocation with pluggable authentication.
  - Separate membership registry and allocation service for Mix, with its own rate-limit parameters.
- Mix and Delivery packaged as a single module, deployable as an entry, exit, or intermediate node.
  - Basic key rotation for forward secrecy.
  - Poisson-rate cover traffic generation.
- Service Discovery adopted as a Delivery plugin, with a simplified module and API.
- De-MLS integration in `libchat` hardened against malformed messages and repeated membership operations.
- Oracle nodes fetch prices from multiple independent sources, with basic dispute detection.
- Zerokit release with Poseidon2 support, runtime validation of resource/hash-function combinations, and static analysis of Poseidon and Poseidon2 circuits.

## Storage

- Faster downloads over mix; target at least 20% improvement, subject to measurement.
- Naming service: stable identifiers can point to different content IDs (CIDs) as content changes.
- Service Discovery for Mix and DHT-proxy pools, removing manual pool configuration.
